# Екосистема для авто-бізнесу

Комплексна платформа для СТО та шиномонтажу: клієнтський сайт із записом на сервіс і "Гаражем" авто + окрема CRM для бек-офісу. Два репозиторії, спільна база даних.

## Що це

Особистий проєкт-прототип для знайомого власника СТО. Розроблявся з нуля без попереднього IT-досвіду через AI-асистований підхід: продуктові рішення, архітектура та вимоги — мої; код пише AI за специфікаціями.

## Стек

**Цей репо — Turborepo монорепо (сайт + API)**

| Шар | Технологія |
|-----|-----------|
| Монорепо | Turborepo + `@auto/types` (shared types) |
| Frontend | Next.js 15 App Router + TypeScript |
| Backend API | NestJS + TypeScript |
| ORM | Prisma |
| Auth | Phone OTP (кастомний) — SMS через BullMQ чергу |
| SMS-шлюз | TurboSMS / SMS-Fly (UA) |
| Сховище фото | Cloudflare R2 (presigned URL flow) |
| Черги | Redis + BullMQ |
| БД | PostgreSQL |

**CRM** (`auto-crm`) — окремий проєкт на спільній БД

| Шар | Технологія |
|-----|-----------|
| Backend | FastAPI (Python) + SQLAlchemy |
| Міграції | Alembic (тільки `crm_*` таблиці) |
| Frontend | Vite + React + TypeScript + TanStack Query |
| Auth | Email + Password, JWT (акаунти створює адмін) |

## Архітектура

```
Клієнт (браузер)
  │
  ▼
Next.js 15 App Router
  │  JWT cookie
  │
  ▼
NestJS API
  ├── /auth         — Phone OTP, JWT
  ├── /bookings     — запис на сервіс, слоти
  ├── /vehicles     — гараж клієнта
  ├── /catalog      — оголошення авто
  ├── /internal/*   — захищені ендпоінти для CRM
  │     ├── /storage/upload-url  — presigned URL для R2
  │     ├── /bookings/:id/status — зміна статусу + SMS
  │     ├── /sms                 — SMS шаблони
  │     └── /service-records     — writeback до Гаража
  │
  └──► PostgreSQL
         ├── site-таблиці  (Prisma)
         └── crm_* таблиці (Alembic, власність CRM)

CRM (FastAPI) ──► читає site-таблиці через SQLAlchemy readonly моделі
                  ──► пише лише crm_* таблиці
                  ──► викликає /internal/* NestJS ендпоінти
```

## Клієнтський сайт

**Booking flow** — 4-кроковий wizard: телефон → авто → послуга → час. Гостьовий флоу без примусової реєстрації.

**"Гараж"** — клієнт зберігає свої авто. Кнопка "Записати на сервіс" прив'язує авто до нового запису.

**Тіньові акаунти** — клієнт, якого додає CRM-менеджер, стає shadow user (`status = 'SHADOW'`). При першому вході через сайт конвертується в повноцінний акаунт.

**Каталог авто** — оголошення з фільтрами (марка, ціна, рік). URL params синхронізуються для shareable посилань.

**Профіль** — перегляд і редагування даних, список усіх записів зі статусами.

## CRM (бек-офіс)

### Ядро
- **WorkOrders → Invoices → Payments** — повний цикл: наряд-замовлення з позиціями (послуги + запчастини) автоматично генерує рахунок; підтримка часткових оплат, ПДВ, знижок
- **Каса** — відкриття/закриття зміни касира, прив'язка транзакцій

### Склад
- Каталог запчастин, облік залишків по складах, замовлення постачальникам
- Списання запчастин при закритті WorkOrder — автоматичне

### Аналітика (6 звітів)
Доходи, P&L, витрати по категоріях, навантаження механіків, популярні послуги, вартість складу. Recharts з `DateRangePicker`.

### Вхідні заявки
CRM читає booking-записи з сайту → менеджер підтверджує/скасовує → NestJS надсилає SMS клієнту → при виконанні `IN_PROGRESS → READY` CRM пише service record назад до Гаража клієнта.

### RBAC
Адмін-конфігурована система прав: ролі + набори permissions (рядки типу `workorders:read`, `cash:open_session`). Sidebar показує секції залежно від прав поточного staff user.

### Каталог авто (з CRM)
CRUD оголошень зі зміною статусів (`AVAILABLE → RESERVED → SOLD`). Upload фото: CRM запитує presigned URL у NestJS → браузер пише напряму в R2 (CRM не тримає R2 credentials).

## Ключові архітектурні рішення

**Розділені міграції** — Prisma та Alembic ніколи не заважають одне одному: `crm_` prefix як жорстка межа власності.

**Presigned URL relay** — CRM не тримає R2 credentials; NestJS виступає посередником з `X-Internal-Key` авторизацією.

**SMS через чергу** — BullMQ з retry; SMS не блокує HTTP response.

**Shadow user без гонки** — `IntegrityError` перехоплюється, обидва concurrent inserts прив'язуються до одного запису.

**Service records writeback** — при закритті замовлення дані сервісу автоматично з'являються в Гаражі клієнта на сайті; при помилці — amber banner у CRM без блокування основного флоу.
